# Масштабирование

Документ отвечает на три вопроса: **что вообще нужно масштабировать, в каком
порядке и где проходит реальный потолок.** Все цифры ниже измерены на
продакшен-хосте, а не взяты из документации платформ.

## TL;DR

| Что | Нужно для масштаба | Примечание |
|---|---|---|
| Аккаунты Instagram | **да, но только для каруселей** | видео качается анонимно, фото-посты — нет |
| Аккаунты TikTok | **нет** | работает полностью без кук |
| Аккаунты Google/YouTube | **нет** | публичные видео качаются без сессии |
| Прокси / резидентные IP | **да, вместе с аккаунтами** | 20 аккаунтов с одного IP = паттерн ботнета |
| CPU / RAM | почти нет | 0.03% ядра на текущей нагрузке |
| Диск | почти нет | автоочистка, пик ~30 МБ |
| Трафик | основная денежная статья | ~2 МБ на ролик, 60 МБ на 4K |
| Ручной труд | **главный потолок** | обновление куок не автоматизируется |

## Что измерено про аккаунты

### Instagram — аккаунт нужен только для каруселей

Раньше здесь было замерено обратное: Reel без кук якобы отдавал страницу гостя
(`__user=0`, без класса `logged-in`) и доступа не было. **Замер был неполным** —
смотрели на один эндпоинт и сделали вывод про платформу.

Перепроверено на конкретном Reel, который стабильно падал с `HTTP Error 400`:

| Путь | Результат |
|---|---|
| Куки, приватное API `media/<id>/info/` | ❌ `400` + `{"message": "checkpoint_required"}` |
| Без кук, публичная страница | ✅ 12 форматов, файл 963 917 байт, h264 720×1280 |

Ещё три публичные ссылки (Reel и обычный пост) дали 9, 5 и 12 форматов без
кук. Четвёртая отдала `empty media response` — пост недоступен, а не «нужна
сессия».

**Значит:** для видео аккаунт не нужен, публичный контент scraping'ом берётся.
Нужен он для **фото-каруселей**: gallery-dl без кук получает
`HTTP redirect to login page`. Приватные посты тоже требуют сессии — но это
редкий случай.

### TikTok — аккаунт не нужен

Запрос видео с **нулевыми куками** отдаёт 391 КБ страницы с встроенными
видеоданными (`playAddr`/`videoUrl` присутствуют). Бот в коде для TikTok
куки и не передаёт, и при этом стабильно качает.

Серия из 10 запросов подряд с интервалом 1.2 с — 10/10 успешных.

### YouTube — аккаунт не нужен

Листинг форматов с куками и без них даёт **побайтово идентичный** вывод
(60 строк, `diff` не находит разницы), включая 4K. Полная загрузка 27.8 МБ
без кук проходит успешно.

Куки YouTube влияют только на закрытые видео, подписки и возрастные
ограничения — это не проверено, публичных примеров под рукой не нашлось.

## Почему аккаунтов мало

Аккаунт снимает лимит **на аккаунт**. IP снимает лимит **на IP**. Это
разные ограничения, и при масштабе работает только их комбинация.

20 аккаунтов с одного адреса — это ровно тот паттерн, который выглядит как
ботнет и приводит к бану пачкой. Поэтому аккаунты и IP масштабируются
**вместе**: 5 аккаунтов на 5 разных IP безопаснее, чем 20 аккаунтов на 1 IP.

Лимит по IP существует уже сейчас, до всякого масштабирования, и бьёт он не
по частоте запросов, а по самому аккаунту. Во время тестов Instagram отдавал
`429` на один из эндпоинтов, а позже перевёл сессию в режим чекпоинта:
`400 checkpoint_required` на каждый аутентифицированный вызов, при куках,
которые формально ещё годны. Это и есть главный аргумент за резидентные IP —
не «чтобы не банили за частоту», а чтобы аккаунт не улетел на ручную
перепроверку. Проба живости сессии трактует `429` как «вероятно живо», чтобы
кратковременный лимит не вызывал ложную тревогу, а вот чекпоинт считает
поломкой — он не проходит сам.

## Потолок по ресурсам

Замеры на текущем хосте (1 ядро, 1.9 ГБ RAM):

| Параметр | Значение |
|---|---|
| CPU на всю нагрузку | 0.1 мин за ~5 ч аптайма (~0.03%) |
| RSS бота | ~180 МБ |
| Трафик на видео | 1.04–1.18× размера файла на вход + 1× на выгрузку в Telegram |
| Размеры роликов | TikTok 0.4–2.9 МБ, Reels ~2 МБ, YouTube 4K 27.8 МБ |
| Диск под контент | пик ~30 МБ, чистится автоматически |

Просчитывая трафик:

| Нагрузка | Трафик/мес | VPS | Аккаунтов Instagram |
|---|---|---|---|
| 100/день | ~19 ГБ | 2 vCPU / 2 ГБ, ~$10 | 1 |
| 1 000/день | ~190 ГБ | 2–4 vCPU / 4 ГБ, ~$25 | 2–3 |
| 10 000/день | ~1.9 ТБ | 4 vCPU / 8 ГБ + резидентные IP, ~$60–100 | 10–20 |

Трафик укладывается в бесплатные лимиты большинства VPS. Дорожают не
серверы, а аккаунты — и не деньгами, а ручным трудом.

**Текущий хост под сервис не подходит:** 1 ядро, 0.4 ГБ доступной RAM, swap
уже задействован, плюс пять других ботов.

## Главный потолок — не железо

**Куки не автоматизируются.** Обновление — ручной экспорт из
залогиненного браузера раз в несколько недель. Instagram блокирует
автоматизацию, поэтому закрыть это скриптом нельзя. На 10 000/день это
20–40 ручных операций в месяц, то есть нужен постоянный человек.

**Перепроверка аккаунта бьёт даже по живым кукам.** Чекпоинт прилетает
не по сроку годности, а когда Instagram решает, что вход был «не оттуда».
Наблюдённый случай: `sessionid` оставался валидным ещё 361 день, а API
уже не отвечал. То есть график обновления куок не по расписанию, а по
событию — и это добавляет ручную работу сверх планового.

**Аккаунт можно потерять.** Куки принадлежат живому личному аккаунту.
Публичный бот под нагрузкой привлекает внимание, и банят именно его. Это
реальный личный риск, а не абстрактная метрика.

**ToS.** Скачивание и пересылка видео нарушает правила всех трёх платформ.
Для личного бота это нормально; публичный сервис превращает оператора в
распространителя контента с чужими правами — зона DMCA-удалений и
зависимой от юрисдикции ответственности.

## Порядок действий

1. **До любого масштаба** — настроить `ADMIN_CHAT_ID`, чтобы протухание куок
   приходило алертом, а не жалобой. Уже реализовано: `/id` и `/status`.
2. **Замерить реальный потолок Instagram** на своём аккаунте: сколько Reel в
   час проходит до `429`. Эта цифра и задаёт, сколько аккаунтов нужно.
3. **Второй аккаунт + второй IP** — только после пункта 2, иначе непонятно,
   упирается ли лимит в аккаунт или в адрес.
4. **Остальное не трогать**: CPU и диск упрутся сильно позже.

## Проверка живости сессии

Бот проверяет куки каждые `HEALTH_CHECK_INTERVAL_HOURS` (по умолчанию 6) и
пишет в админский чат при смене состояния.

Проба: `GET https://www.instagram.com/api/v1/accounts/edit/web_form_data/`

- `200` + JSON → сессия живая
- `302` → мёртвая, редирект на логин
- `400` + `{"message": "checkpoint_required"}` → куки формально живы, но
  Instagram требует ручную проверку входа. **Считается поломкой**, потому
  что аутентифицированное API не работает. Видео продолжает качаться
  анонимно, карусели — нет.
- `429` / сетевой сбой → «вероятно живо», тревоги нет

Сигнал выбран эмпирически: проверены четыре состояния кук — настоящая
сессия, отозванный `sessionid`, только `csrftoken` и пустая банка. Только
настоящая вернула `200`, ложных «живо» не бывает.

**Проверки сроков недостаточно.** Отозванная до истечения сессия на диске
выглядит валидной — ловит только сетевая проба.
